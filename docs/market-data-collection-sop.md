# 食用菌新市场数据采集 SOP

本文是因恒科技开拓新国家和新区域时的统一数据采集流程。适用于零售价格、批发线索、贸易、生产、物流、政策和市场事件。中亚、东南亚及后续市场共用本流程；国家、语言、渠道和商品规则放入各自的市场接入包。

## 一、不可变的采集原则

1. 只采集公开、可追溯、可重复访问的信息，不绕过登录、验证码或访问控制。
2. 价格、币种、规格和具体品种必须都有页面证据，否则不进入客户可见数据。
3. 无数据、无商品、缺价或采集失败记录为具体缺口，不用 `0` 代替。
4. 保留原始标题、原始价格文本、原始规格、来源链接、采集时间和页面指纹，保证可追溯。
5. 客户版只读取通过质量门禁的记录；采集错误、失败原因和内部复核信息只用于运维。
6. 国家数量、平台数量和商品数量不是上线标准；可持续采集和可比价格才是。

## 二、新市场接入七阶段

### 阶段 1：定义市场边界

先建立市场接入卡，再寻找数据源。接入卡至少包含：

- 国家与 ISO 代码。
- 首都、主要消费城市和需要区分的州、省或邮编。
- 本币、时区、本地语言和平台常用语言。
- 目标客户、主力品类、商品形态和预计更新频率。
- 零售、批发、贸易、生产、物流和政策的业务优先级。

**通过条件：** 每个国家都有明确的地理粒度、监测品类、更新频率和数据用途。

### 阶段 2：建立本地商品词典

以统一品种 ID 为主键，建立“中文规范名＋英文名＋学名＋本地名＋借词＋排除词”词典。

每个检索词应标记：

- 语言和词源。
- 对应的具体品种。
- 是精确词还是泛称。
- 是否容易命中非食品、餐饮菜品或保健品。
- 适用的商品形态：鲜品、干品、冷冻、腌渍或其他。

泛称可用于发现商品，不能单独用于确定品种。

**通过条件：** 目标品种至少有一个本地平台实际使用的检索词，并完成非食品排除规则。

### 阶段 3：建立渠道地图

按下列顺序寻找渠道，不以搜索结果排名代替渠道验证：

1. 当地连锁商超和生鲜零售商。
2. 有明确门店或配送区域的本地电商。
3. 市场型平台和分类信息平台。
4. 餐饮供应、批发和 B2B 平台。
5. 政府、海关、统计、检疫和认证机构。
6. 联合国、FAO 等国际统计源。

每个渠道记录名称、国家、城市或门店、渠道类型、公开入口、可见字段、更新频率、访问限制和备用源。

渠道状态统一为：

- `candidate`：已发现，尚未验证。
- `probing`：正在试采。
- `active`：已通过上线门禁。
- `gap`：可访问，但当前没有目标商品或明确价格。
- `blocked`：受访问控制、地域或技术条件阻断。
- `retired`：页面失效、长期不更新或数据已不可追溯。

**通过条件：** 零售价格至少有两个彼此独立的候选渠道；贸易、生产和政策有对应的官方或国际来源。无法满足时，应在市场接入卡中缩小数据产品范围。

### 阶段 4：试采与适配

按以下优先级选择采集方式：

1. 公开的结构化接口或页面结构化数据。
2. 服务器直接输出的商品页或列表页。
3. 公开搜索页。
4. 合规的浏览器渲染。
5. 固定商品页作为补充，不作为扩品唯一方式。

适配器必须输出统一原始字段：平台、商品 ID、国家、城市、采集点、商品链接、原始标题、当前价、常规价、促销价、币种、规格、库存状态、原始价格文本和页面指纹。

试采期必须覆盖：有货、无货、促销、多规格、无规格、非菌类误命中、页面改版和网络失败。

**通过条件：** 适配器有离线页面样本和自动测试，且一个来源失败不会覆盖同平台或同国其他来源的成功结果。

### 阶段 5：标准化与质量门禁

每条商品依次处理：

1. 清理标题噪音，保留原始文本。
2. 识别具体品种，排除非食品。
3. 识别商品形态、品牌、等级和包装类型。
4. 解析净重、体积、数量和组合装。
5. 计算标准公斤数和本币每公斤价。
6. 使用有来源和时间戳的汇率计算美元每公斤价。
7. 按“国家＋品种＋形态”执行合理区间和同组异常检查。

正式价格必须同时满足：

- 品种已分类，且达到设定的可信阈值。
- 当前价大于零，币种与国家一致。
- 净含量来自页面标题、结构化数据或可回看的商品证据。
- 美元每公斤价可复算。
- 未触发未解释的异常标记。

异常记录保留原始证据和原因，不进入汇总和客户版。小包装、精品、有机和会员价等不能与普通大包装直接比较，必须保留对应标签。

**通过条件：** 任意一条客户可见价格都能从原始页面重新计算出品种、规格、本币价和美元每公斤价。

### 阶段 6：连续运行验收

新市场先进入观察期，不直接进入客户日报。观察期每次采集都应记录：

- 开始和结束时间。
- 访问页数和发现商品数。
- 通过门禁、被拒绝和需要处理的记录数。
- 失败代码、失败页面和平台状态。
- 每个检索词的发现数和有效数。

建议的正式上线门禁为：

- 完成不少于 14 个自然日的连续运行。
- 至少有 2 个彼此独立的活跃零售来源；如市场客观上只有单一渠道，需单独批准数据产品范围。
- 主力品种在同一采集点可重复观测，不依赖一次性搜索结果。
- 同一商品的价格、规格和门店归属在重复采集中保持一致。
- 来源失败会触发明确告警，不会生成零价、过期价或错国家数据。

14 天是新市场的默认验收周期；市场波动大、平台依赖邮编或季节性强时，应延长观察期。

### 阶段 7：上线与维护

通过验收后，按下列顺序上线：

1. 启用定时采集和来源健康监控。
2. 生成国家、城市、品种和形态粒度的每日汇总。
3. 只将通过门禁的数据接入客户界面和报告。
4. 为新国家添加报告范围、优先级和表达规则。
5. 对连续失败、商品数突变、规格解析突变和价格分布突变设置告警。

上线后的来源处理：

- 单次失败：保留上次历史记录，当日不生成新价。
- 连续失败：将来源转入检修，启用备用来源。
- 页面改版：用新页面更新离线样本和解析测试后再恢复。
- 商品下架：记录库存或活跃状态，不删除历史数据。
- 渠道永久失效：标记为 `retired`，保留历史归属。

## 三、市场接入包

新区域不复制采集主程序，只新增或修改市场接入包。一个完整接入包包含：

| 配置类别 | 必备内容 |
|---|---|
| 市场 | 国家、城市、州/省/邮编、时区、币种、统计代码 |
| 语言 | 本地语言、平台常用语言、品种词、泛称和排除词 |
| 商品 | 目标品种、商品形态、包装单位、等级与特殊标签 |
| 渠道 | 平台、门店或配送区、公开入口、采集方式、备用源 |
| 标准化 | 质量/体积/数量换算、税前税后、会员价、促销价、箱规规则 |
| 质量 | 分类阈值、价格合理区间、同组比较维度、异常处理 |
| 外部数据 | HS 编码、官方统计、海关、检疫、认证、物流和政策源 |
| 输出 | 更新频率、客户可见范围、报告优先级、数据说明 |

市场接入包与通用采集引擎之间只通过统一字段和状态交互。平台特殊逻辑属于适配器，不得写入通用标准化和报告逻辑。

## 四、数据类型的附加门禁

### 零售和批发价格

- 零售挂牌价、会员价、促销价、配送价和批发箱价分开保存。
- 门店、城市、邮编或配送区会影响价格时，该位置是必填维度。
- “价格面议”、“起售价”和缺少箱规的批发价不进入可比价格。

### 贸易和生产

- 保留报告国、伙伴国、HS 编码、年月、金额、数量、单位和数据状态。
- 进口申报、伙伴国出口镜像和估算值分开存储，不合并成一个“市场规模”。
- 生产统计保留官方估算或插补标识。

### 政策和事件

- 只接收可追溯到政府、海关、检疫、认证机构或法定统计机构的原始公告。
- 必须保留机构、标题、发布日期、原始链接和获取日期。
- 搜索引擎、新闻聚合页和媒体报道可用于发现线索，不能替代官方原文。

### 物流

- 路线必须包含起点、终点、运输方式、货物条件、报价时间和来源。
- 通道存在、运输时效和运价是三个不同事实，不得相互推导。
- 没有可追溯的承运或官方信息时，不生成时效和运价。

## 五、新市场上线检查表

以下项目全部通过后，新市场才能进入客户数据和报告：

- [ ] 市场接入卡完整，地理粒度和更新频率明确。
- [ ] 品种词典、检索词、泛称和排除词已验证。
- [ ] 渠道地图完整，渠道状态和备用源明确。
- [ ] 适配器完成离线样本和自动测试。
- [ ] 规格、币种、汇率和每公斤价可复算。
- [ ] 品种、形态、包装、会员价和促销价不混用。
- [ ] 异常、缺口和阻断状态不会进入客户可见数据。
- [ ] 已完成连续运行验收。
- [ ] 定时任务、失败告警、来源健康和备用源机制已启用。
- [ ] 客户界面和报告只读取通过门禁的数据。
- [ ] 报告的市场范围、优先级和数据说明已同步。

## 六、变更要求

- 新增国家或平台时，同步更新市场接入包、测试和来源状态。
- 修改品种、规格、价格或发布门禁时，同步更新日报生成 Prompt 和对应测试。
- 通用规则修改必须提交到 Git；单个平台的调查记录保留在对应的数据源状态文档中，不写回本 SOP。

## 七、项目内的执行入口

本 SOP 定义“新市场如何接入”。当前程序的实际配置与执行入口以下列位置为准：

- 国家、币种、平台和目标品种：`pipeline/config.py`。
- 多语检索任务：`pipeline/search_queries.py` 中的 `COUNTRY_SEARCH_TERMS`。
- 平台采集：`pipeline/adapters/` 及 `pipeline/fetch_price.py` 中的 `SOURCES`。
- 品种、规格和形态标准化：`pipeline/taxonomy.py` 和 `pipeline/product_dimensions.py`。
- 记录复核与价格异常：`pipeline/review.py` 和 `pipeline/sanity.py`。
- 数据存储契约：`db/schema.ts`。
- 客户报告：`AGENTS.md`、`pipeline/report_prompts.py` 和 `pipeline/generate_report.py`。
